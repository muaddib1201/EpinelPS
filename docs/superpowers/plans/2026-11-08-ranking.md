# Campaign and corporation rankings implementation plan

Goal: implement hard campaign and four corporation leaderboards, milestone achievements, server rewards and cumulative rank rewards, then deploy using the authorized collaboration workflow.

Architecture: use the shipped RankingTable, RankingPointTable, TriggerTable and RewardTable as authority. Keep milestone winners and claims durable, use the JSON save lock for ranking settlement and claim mutations, and retain trigger deliveries as a durable outbox. Use authenticated protobuf handlers and real isolated JSON/SQLite regression fixtures.

Constraints: own registered worktree only; no live fixture writes; integrate, sync, all tests, publish, seal and deploy. Game exit check, backups, rollback and health checks in sealed installer. Existing player progression is preserved.

- [ ] Write and run failing authenticated overview/detail tests; inspect shipped target and point rows.
- [ ] Load ranking tables; calculate hard campaign and unique owned corporation growth points, stable ranks, public profiles and zero-score personal entries.
- [ ] Verify invalid types, bans, authentication, duplicates and overflow bounds.

## Task 2: milestones and rewards
- [ ] Write failing milestone, top-ten, cumulative trigger and reward idempotency tests.
- [ ] Persist one achievement per target and user, retain historical winners, expose achievement leaderboards and cumulative triggers.
- [ ] Implement single-category/all server rewards and cumulative reward delivery using existing reward/mail conventions; save rollback and durable trigger delivery.
- [ ] Verify concurrency, refresh, save failure, reload and a fresh process.

## Task 3: integration and deployment
- [ ] Commit; independent code review; address important findings with reproductions.
- [ ] Integrate and sync; all isolated regression suites; publish latest integration.
- [ ] Prepare installer with game-exit guard, complete program/save backups, rollback and authenticated health probes; seal, check-release, deploy.
- [ ] Verify installed hash and live protobuf boards/reward state; record evidence and client acceptance limitation.

Review focus: historical ordering cannot be reconstructed before rollout; bootstrap deterministically from saved progress. Never invent earlier timestamps. Future achievements retain first observation order. Reward retries cannot issue duplicates. Reads must not wipe other gameplay state. Unsupported tower/museum types must not contaminate the five requested boards.
