# NPC Teams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build sustainable owned-SSR NPC teams, five collection/skill tiers, migrate the current 30, and expand the deployed population to 100.

**Architecture:** Add a pure team selector and burst validator driven by current static data, separate collection tiers from activity tiers, and reconcile only managed NPC saves. Use the existing snapshot transaction and durable creation journal for migration and target-count expansion.

**Tech Stack:** C#/.NET 10, existing JSON database, SQLite profiles, Razor admin, executable regression harnesses.

**Spec:** `docs/superpowers/specs/2026-11-07-npc-teams-design.md`

## Global Constraints

- Preserve all existing owned character IDs, serial numbers, levels, grades, story progress, guild membership, activity schedules and non-NPC users.
- Collection tiers use SSR counts 5–12, 13–18, 19–24, 25–30, 31+; main skill ranges 2–3, 4–5, 6–7, 8–9, 9–10.
- Do not assume conditional cooldown reduction when proving a team sustainable.
- Keep the existing population limit 200; this deployment target is exactly 100.
- Work from the current modified source; do not discard the previous stacked fixes. Back up touched originals. Git metadata is read-only; do not commit unrelated work.

## Review Focus

- Sparse inventory: return a valid slower loop or a clear failure without adding/removing cards.
- Re-entry and all-stage units: follow the actual stage transition and prevent reuse within the same chain.
- Save failure/restart: roll back and avoid remigrating, duplicate population or human mutations.
- Skills and new recruits: train selected serial numbers and respect collection tier caps without downgrading existing higher skills.
- Arena squads: keep the main squad synchronized and special rounds distinct; do not modify human teams.
