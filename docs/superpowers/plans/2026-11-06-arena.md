# Arena Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the core implementation and superpowers:dispatching-parallel-agents for the independently owned harmony cube subsystem. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 新手与特殊竞技场接入托管玩家，完成编队、匹配、真实客户端战斗、排名、记录及奖励。

**Architecture:** MVC 控制器统一鉴权并按 user -> JsonDb.SaveLock 加锁。ArenaService 按单调时钟推进本服日/赛季，再执行请求；开始快照与结果回执写入 JSON 原子存档，任务触发器通过待交付记录写入 SQLite。独立 ArenaHarmonyCubeService 只负责竞技场魔方配置。

**Tech Stack:** 现有 net10.0、ASP.NET Core、Google.Protobuf、Newtonsoft.Json、SQLite、MemoryPack 数据表。

**Spec:** ../specs/2026-11-06-arena-design.md

## Global Constraints

- 只做新手和特殊竞技场；冠军仍不可用，不生成假回放。
- 新手每日免费 3 次（配置 ArenaTodayMaxCount），特殊为 ArenaTable 的 2 次；额外只扣已有票，不隐式扣钻。
- 特殊三队各五人，同名角色不得重复；不足 15 人不伪造角色。
- 现有完整脏工作区包含已安装修复；原地编辑并备份原文件，.git 为只读，不创建丢失这些修复的干净分支。
- 测试只用测试输出目录的存档，不改真实账号进度；安装先停止服务、备份，游戏运行则等待退出。
- 私服连续 14 天赛季，起点 2026-11-06 的 UTC 日重置边界；运行时不倒退，不回溯上线前奖励。

## Review Focus

- 同一目标连续正常挑战应结算两次，旧包重试只结算一次；无传输 Nonce 的结果不得猜测是哪一场。
- 交换特殊排名前按旧段位计息；新玩家加入与无效队伍不能造成重复排名。
- 失败存盘不能留下已扣票、已发奖、部分换位或部分赛季结算。
- 存档恢复与时间回拨不能重复发放每日或赛季奖励；只累积真实加入后的时间。
- 当前客户端缺少新手静态玩法/段位表；服务端测试不能冒充客户端可用性验收。
