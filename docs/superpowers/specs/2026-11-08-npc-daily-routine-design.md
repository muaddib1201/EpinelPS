# NPC 每日五阶段日程

用户已在本会话明确授权直接实现：保留现有 NPC 与进度；每天一轮；半小时内五阶段；资源、任务点数与联盟贡献实际结算；重启不得重复。

## 方案

采用服务器内单一定时入口执行固定计划，替换随机行动与 72 小时离线追赶。保留现有玩家身份、角色、练度、队伍、联盟及历史资料，不重新创建 NPC。沿用 C#、JSON 存档、SQLite 任务触发器与现有玩法结算助手。

选择理由：用户已经选定固定阶段动作。逐 NPC 线程/客户端没有必要；继续随机养成不符合半小时完成每日资源活动的要求。

## 日程

每个游戏日首次检查时建立计划，在第 6、12、18、24、30 分钟执行五阶段；轮询延迟时依次处理已到期阶段。以现有 ResetHourUtcTime 区分游戏日。每日最多一轮，完成后等待下个游戏日。重启从持久阶段续跑；不补发历史日期日常。暂停不推进，恢复保留已完成阶段并安排剩余阶段。

1. 领取前哨实际累计收益、当天免费歼灭、已经完成的派遣、好友赠点/领取；开始可执行的新派遣。
2. 按当日额度咨询、消耗已有赠礼材料；按已有资源升级角色/同步器和技能、消耗重复角色材料突破。
3. 使用可用招募券/友情点数/免费钻石招募；结算已解锁模拟室、拦截战资源。招募设有限日预算，不动付费钻石。
4. 顺序推进有效主线和开放塔层，使用简化战力条件判定，不执行战斗；结算首通资源、主线任务与剧情状态。
5. NPC 之间完成可用免费竞技场次数、联盟射击场活动，领取实际达到条件的每日/每周/成就奖励与点数奖励；每日任务点数走既有 GuildActivity 结算。

本日计划动作受解锁、次数、材料、货币和现有数据表约束；不满足时记录跳过。当前服务端未实现的玩法不伪造成功。长期派遣按真实结束时间在以后日程领取，不能为了三十分钟窗口提前领奖。

## 结算与恢复

阶段业务变更、完成编号、行动日志及任务通知写入同一原子 JSON 保存。使用 RewardMutationScope 抑制中间保存并捕获任务触发器，成功保存后将持久 outbox 幂等投递到 SQLite。失败恢复本阶段内存，包括受影响的联盟、竞技场世界和对手。重启后已完成阶段不得再次执行；通知投递失败只重试通知。

咨询、抽卡、塔、主线、奖励等复用现有业务助手；必要时从 HTTP 处理函数提取纯结算入口。任务奖励只领取已经满足条件的定义，不能因原接口不校验而任意领取。触发器读取合并 SQLite、持久待投递记录及当前阶段记录，并按既有 UTC+9 储存时间换算日/周窗口。新增 NPC 任务不能再次走旧固定联盟贡献。

## 验证与交付

在本会话隔离 JSON、SQLite 和静态数据副本验证五阶段时限、资源消耗与收益、任务/点数/联盟联动、身份和进度保留、同时间重复检查、跨日、暂停、时钟回退、保存失败和独立进程重启。运行相关及全套回归，提交并使用 integrate/sync 统一集成。发布/安装遵循项目唯一入口，不直接操作线上存档。客户端验收与服务端检查分别报告。
