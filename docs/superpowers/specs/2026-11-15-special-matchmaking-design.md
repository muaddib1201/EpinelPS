# 特殊竞技场向上匹配

用户已要求修正特殊（高级）竞技场，只匹配排名更靠前的对手，尽量接近官服，测试通过后部署。复用当前会话独立工作树，从最新集成基线 c28c2c2 开始，保留新人匹配与装备交换等已集成修复。

## 依据与方案

公开实机玩法说明描述三个更高挑战段位各一名对手、多人段位内刷新、挑战者单人段位固定，前 3 名分别最多有 2/1/0 个目标：https://www.prydwen.gg/nikke/guides/pvp-intro 。这不是官方服务器源码。段位范围使用本地客户端 TierTable，而不猜测战力阈值或假设 Priority 连续。

比较过只过滤现有战力窗口（仍会漏人）与随机选择任意更高名次（跳过挑战段位）。采用最近三个有合法对手的更高段位，每档一人，按战斗名次升序显示。段位内按玩家、赛季、段位和 ID 散列后，使用现有 SpecialRefresh 游标轮换；单人段位刷新不变。

始终只接受合法参赛者中 `0 < 对手 SpecialRank < 自己 SpecialRank`，不区分真人和 NPC，不按战力截取 12 人。空段位跳过；离线稀疏组若仅有同段位的更高名次者，则回退为最近最多三名更高者。第 1 名返回空目录。游标兼容负值和 long.MaxValue，沿用存档字段。

新开战在扣免费次数/票券前重新检查向上资格，不合格返回 409。已开始战斗及其重试维持原快照；结算仍使用现有换位和时间积分逻辑。NPC 特殊竞技场从相同候选段位中选合法 NPC，找不到目标就不消耗次数；保持不自动攻击真人的既有策略。

不改新人匹配、赛季积分计算、奖励、票券价格、阵容或存档结构。本次是对公开玩法与客户端表的还原，不声称取得官服完整抽样算法。

## 验收

HTTP 回归覆盖 1/2/3 名的 0/1/2 目标、11/16/31 名的段位边界、多人轮换覆盖、单人固定、战力/账号类型独立、稀疏组、非法阵容过滤、游标和新人模式隔离、拒绝过期低排名目标且不扣次数，以及保留进行中战斗。NPC 回归覆盖只向上攻击和榜首无目标不扣次数。

按项目统一入口集成、同步、相关回归、源码备份、publish、seal、check-release、deploy。新安装脚本包含游戏退出检查、冷备份、失败回滚、HTTP/TLS、JSON 人类存档及 SQLite 一致快照完整性/逻辑内容检查。游戏退出后才能安装，客户端验收单独报告。
