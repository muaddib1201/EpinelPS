# 新人竞技场匹配修正

用户要求修正新人竞技场刷新匹配，尽量接近官服，解决高排名对手无法出现的问题，测试通过后部署。沿用当前会话独立工作树和统一集成、备份、封存、部署流程。

## 依据与边界

- 当前代码只轮换战力最接近的 12 人；隔离存档以 1807 分模拟时，9 名 1820 分的对手全部被排除。
- 官方 2026-08-13 公告涉及特定分数差距对手不出现的问题；2023-08-03 公告要求新人对手清单从高到低排列。来源：https://nikke.hotcool.tw/m/News_detail-215 和 https://nikke.hotcool.tw/m/News_detail-37 。
- 已检查本地 GameSettings/Arena 数据，没有可用于还原官服抽样范围和权重的配置。因此下面的三档策略是本地近似，不能宣称与官服精确一致。

## 方案

考虑过全组随机三人（仍可能很久看不到更高名次）和固定积分窗口（缺少官方阈值，仍可能排除对手）。采用积分/排名分档并轮换，避免硬编码积分范围和战力窗口。

1. 从现有合法参赛者中排除本人，不额外优待 NPC。
2. 首先取一名排名更高的对手；然后从剩余对手中取积分差最小档的一人；再取一名排名较低的对手。某档缺人时，从剩余最近积分档补齐，最多三名且不重复。
3. 各档按玩家、赛季、档位和对手 ID 生成稳定散列顺序，使用既有 RookieRefresh 游标轮换；先轮换完整排名档，再跳过本页已选者。因此稳定参赛集合中的每名更高或更低排名对手，在对应排名档的一个完整轮换内都会出现。
4. 返回列表按积分降序、ID 升序，和现有积分榜的同分顺序一致。战力变化不影响候选资格。
5. 沿用原有存档字段；处理旧负游标和 long.MaxValue，避免刷新异常。保留特殊竞技场的现有路径、游标与行为。

不改积分结算、奖励、票券、阵容、赛季、NPC 行为或线上存档。客户端画面验收与服务端验证分别报告。

## 验收与部署

测试必须实际调用竞技场接口，证明战力相差很大的高排名真人和 NPC 都能出现、同分多人不会被 12 人截断、近分和低排交叠时不漏人、列表有序且不重复、人数不足可补齐、封禁/未解锁/非法阵容排除、游标持久化且不改变次数或特殊竞技场匹配。部署前游戏必须退出；程序与存档备份、失败回滚、启动健康和玩家数据保留检查全部在统一部署锁内执行。SQLite 以在线备份 API 从只读连接生成一致快照，检查完整性并比较各业务表的逻辑内容；不得只核对 JSON 或忽略 WAL。
